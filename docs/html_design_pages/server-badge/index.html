Server badge: conduit designs and competitors

Where a running dev server shows, and what tapping it does

What's fixed already: the status glyph stays honest (Q2 A). A server adds a small ◉ :port badge. Tapping it opens the preview, or the Servers card when there are several. A server that stops or crashes just vanishes. These designs vary where the badge sits, where the Servers card lives, the phone flow, and chat links. Rows use conduit's real tokens, glyphs and layout. Use the toggle top right for dark mode.

Sidebar badge placement

6
1

Right column, replaces time

↗

Follows bb, which puts its terminal glyph in the trailing status slot. Departs from everyone by showing the port. Costs the timestamp while serving. t3code: a pulsing teal terminal icon after the title, no port, and the time stays.

2

Context line, after the branch

↗

Follows paseo: a globe and service name on the metadata line, green, red when unhealthy. Title and time stay untouched. t3code: the same teal icon can sit on the branch line, before the PR and diff marks, but with no name or port.

3

Glyph pip plus port in the time slot

↗

No competitor does this. Quietest option: a green pip on the glyph, with the port before the time. Small tap target on phones. t3code: a separate icon; the status glyph itself never changes for a running process.

4

Trailing the title, where the pin sits

↗

Follows t3code exactly: a pulsing teal terminal icon after the title and pin, tooltip '1 terminal process running. Open terminal', no port. Long titles truncate sooner.

5

Port-free dot, count when several

↗

Follows t3code and bb: an icon only. t3code shows one icon whatever the count, with the count only in the tooltip. Smallest, but you only learn the port by tapping.

6

A Serving filter chip and group

↗

No competitor does this; it departs from keeping each row in its honest group. Every preview is easy to find, but an unread session can hide under Serving. t3code: no server grouping found; the row stays where it was and only gains the icon.

The Servers card

4
7

Popover from the row badge

↗

Follows paseo's Scripts menu (open, copy, stop, exit badge) and diri's hover card. Stopped servers stay listed until dismissed. t3code: the row icon opens the terminal. Agent servers are listed in the thread details 'Servers' section, with open and a hover Stop.

8

Header button in the session bar

↗

Follows paseo, whose Scripts trigger sits in the workspace header. Always reachable, but takes header space. Closest to t3code: a per-thread 'Servers' section in its thread details panel, with open and Stop, rather than a header button.

9

Tray above the composer

↗

Follows bb's background-commands card above the composer (capy has an activity bar there too). Costs vertical space in every serving session. t3code: nothing above the composer.

10

Dropped: Crash: red badge, exit code and last log lines

↗

Dropped: you chose vanish-on-exit, like t3code. Kept for comparison. Only paseo shows a red exit badge for a nonzero exit code. Nobody keeps a crash log; this hands the log to the agent in one tap. t3code: no crash state. The terminal prints '[terminal] Process exited' and the Browser shows 'This site can't be reached' with Reload.

Phone over Tailscale (C, with D fallback)

2
11

Badge tap opens a sheet

↗

Departs from 'desktop only', which paseo and bb use. t3code: its phone app streams the desktop's browser if paired with preview access, otherwise 'Preview is only available in the T3 Code desktop app', and the phone row has no terminal icon. Conduit opens the real page through Tailscale.

12

Fallback D: can't forward this one

↗

Follows paseo ('Browser is desktop-only') and bb ('Browser tabs need the desktop app'), but names the reason and the address. t3code: 'Preview is only available in the T3 Code desktop app', with no address or reason.

Chat links and lifecycle

2
13

localhost links become live server chips

↗

bb already rewrites localhost hostnames silently and keeps the text unchanged. This goes further: a chip while the server is live; once it stops, the link goes back to plain text. t3code: ordinary links with a 14px favicon; localhost is not rewritten or marked.

14

One row through a server's life (vanish on exit)

↗

Follows t3code: discovery is live-only, so a stopped or crashed server just vanishes from the row and the Servers card. Only paseo keeps stopped entries. The 'awaited' mark is conduit's own.

Servers as a view, beside Terminal, Diff and Files

5

The row badge is design 5 (an icon, with a count when there are several). The Servers list moves into conduit's views: the right rail on desktop (ViewsRail.svelte), the view cards in the ⋯ sheet on the phone (SessionBar.svelte). Tapping the row badge opens this view. Servers vanish when they exit.

22

Desktop: a Servers button on the views rail, opening a side pane

↗

Follows t3code's per-thread 'Servers' section (open, Stop), but as a view like Files instead of a details panel. Gets ⌥5 like the other views. The pane shows the URL, Open, Copy link and Stop. Costs a pane's width while open, same as Files.

23

Rail button states: always there vs only while serving, and which count mark

↗

conduit's Diff button is always shown, disabled when unused; Terminal shows an accent count for unread output. Options: (a) always shown, dim when no servers, (b) only appears while a server is live, (c) green count, (d) accent count like Terminal, (e) a green dot only. Chosen: (b) when no servers, (d) when there are some, so the rail never carries a dead button and the count matches Terminal's.

24

Not chosen: Servers as a fifth view card in the ⋯ sheet

↗

Keeps the phone's one place for views. Five cards fit at 390px only if each narrows to about 64px, so labels get tight. Tapping Servers opens the full-screen view in card 26.

25

Chosen: view cards scroll sideways, Servers peeks in

↗

Keeps today's card size by letting the row scroll. Servers is easy to miss off the edge, so it comes first (after Chat) whenever a server is live.

26

Phone: the Servers view itself

↗

What the view card or row badge opens on the phone. Same content as the desktop pane, sized for thumbs, with Open going through Tailscale (fallback D shows design 12).

What competitors do

7

Where they converge. Only t3code, bb and paseo mark the sidebar row, each with one icon or name and no port. Most keep a separate server list (t3code, paseo, zeron, diri, capy). Only paseo has stop, restart and an exit state. Only bb rewrites localhost links. Most give up on the phone ("desktop only"). Nobody shows a port on the row or a red crash badge, so designs 1, 3 and 10 are conduit's own.

15

t3code: terminal icon on the row, a Servers section in thread details

↗

t3code 9c6429d74b. The row icon (pulsing teal terminal) covers only servers in t3code's own terminals. Servers the Claude agent starts show in the thread details 'Servers' section: localhost:port over 'Agent · node', click to open, hover to Stop. They stay listed after the turn ends and vanish when they exit. The Browser panel also lists all local servers.

16

bb: shining terminal in the status slot, activity card above the composer

↗

bb 81825aa985. The terminal glyph takes the row's trailing status slot ('Background command running'), and a spinner for agent work can hide it. Above the composer: 'Running 2 background commands'. Chat rewrites localhost hostnames silently; the browser says 'Server not reachable' when it's down. No port list or stop button.

17

paseo: service name on the meta line, Scripts menu with lifecycle

↗

paseo de45902652. The only one with lifecycle actions. The workspace row shows a globe and one service name, green or red when unhealthy, but no port or count, and touch layouts drop it. A Play trigger opens Scripts: status dot, View/Restart/Stop, the URL with Copy, and 'exit N' with Play for stopped ones. Browser is desktop-only.

18

zeron: a Ports card beside the session, server cards on the Browser start page

↗

zeron ab189159f1. No server marker in the sidebar at all. A 272px Ports card in the session inspector lists name and :port; clicking opens the in-app Browser. No stop, restart, copy or crash state. Remote sessions get a banner: 'Localhost opens on this device.'

19

diri: ports on hover, a Links popover, Local servers in the inspector

↗

diri a74e3233a2. Ports never show on the row itself, only in its hover card. A toolbar Link button with a count opens a searchable list where running ports sit between pull requests and links. The inspector has a 'Local servers' card that opens externally. No stop, no crash state, no phone support.

20

monocode: orange bars and process names in the footer

↗

monocode 26465c6209. Project-wide, not per session: the footer shows three pulsing orange bars and the foreground process names ('vite · jest', 'vite ×2'). One process toggles its terminal; several open 'Running terminals'. No ports, no preview, no row marker.

21

capy: dot grids, an activity bar, Services in the + menu (approximate)

↗

capy docs only (2026-10-28). Approximate: the docs describe the parts but not their visuals. A dot grid on the row's right reads Working, Waiting or Failed, and 'Waiting' can cover a long-running command. An activity bar sits above the composer; the + menu lists Services by machine with status dots, logs and relaunch, and Overview lists 'Exposed apps' with preview URLs.
