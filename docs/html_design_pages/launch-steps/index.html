New-session launch steps: 10 designs

TL;DR. t3code puts a live checklist (fetch → check out files → submodules → setup script → start agent) right under your first message, then folds it into one "Worktree ready · 12s" row once the agent starts. Conduit shows a generic working state until Git finishes, then a separate "Setup script running" notice. Below: how t3code does it, what conduit does now, and 10 designs. Every design runs the same fake launch: use Live / Done / Failed at the top right of each card.

What t3code shows, and how

What you see

  • A block under your first message with up to 5 steps: Fetch base branch, Check out files, Init submodules, Run setup script, Start agent.
  • Each step is pending (○), running (spinner plus a shimmer on the label), done (✓), skipped (–), warning or failed (✗), with its own live timer and an overall timer.
  • Check out files shows a real percent. The server parses git's Updating files: 62% (1702/2742) output.
  • The setup step is named after the script and shows its last 4 output lines while it runs and when it fails.
  • Buttons: Details (branch, base, path, command), Open terminal, Work locally (drop the worktree and run in the main checkout), Cancel.
  • When the agent starts, the block collapses to a single "✓ Worktree ready · 12s" row in the turn's work log. If the setup script is async and still running, it moves to a small "Background setup" chip in the working header, with a popover.

How it's built

  • Contract (packages/contracts/src/worktreeSetup.ts): a WorktreeSetupSnapshot with phase, branch, base, path, setup script, an ordered stages array (status, start/end, percent, detail, tail) and a sequence number. Text is clamped to 200, 400 and 1000 characters.
  • Server (apps/server/src/project/WorktreeSetupTracker.ts): an in-memory map of snapshots plus a PubSub. Kept 30s after it finishes. Not persisted. ThreadLaunchService calls stageStatus, stage, appendTail and finish as it works.
  • Transport: a subscribeWorktreeSetup WebSocket stream sends the whole snapshot on every change.
  • Web: MessagesTimeline.logic.ts inserts a synthetic worktree-setup row after the first user message. WorktreeSetupCard.tsx draws it with the same WorkLogRow used for tool calls, which is why it feels native.

What conduit does today

  • Sending from a draft calls CreateSession, which blocks while Git creates the branch and a worktree for every project folder, one after another. The UI shows only a generic working state.
  • The code says it plainly: "no session exists until Git succeeds" (src/lib/server/ws-rpc/sessions.ts). So there's nowhere to hang progress yet.
  • After that, the setup script runs once, in the main folder's worktree. It shows as a separate "Setup script running" notice with raw output (SystemMessage.svelte), built from persisted SessionSetup* events.
  • Conduit's real steps are create branch (git update-ref), check out files (git worktree add, per folder), setup script, start the provider. There's no fetch or submodule step, so the designs below use these four.

Building it in conduit

The catch: branch and checkout happen before the session exists, so they have no event-store home. Two ways round it:

  • A. Launch tracker keyed by the send's inputId (t3code's way). An in-memory snapshot streamed over /rpc, dropped 30s after it finishes. Small change. A reload mid-launch loses the steps, which is fine for a ~10s launch.
  • B. Create the session first, in a launching state, and persist each step. Survives reloads and shows on your phone too. But it breaks "no session until Git succeeds", and failed launches need cleanup.

I'd pick A. The setup script and provider start already happen after the session exists, and setup already writes SessionSetup* events. So the card would read the tracker for the first two steps and the existing events for the last two, with no new persisted state.

Real percent needs git's progress output. t3code parses Updating files: N% (a/b). Without it, checkout can only show a spinner and a timer. Design 7 is the only one that already copes with that.
