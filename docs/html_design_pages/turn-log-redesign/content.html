Short answer: they're two separate features that were each built without the other in mind, and the counter was placed so it copies the layout of a step row.

  • "Loaded" is the generic tool row. The Skill tool's past-tense verb is "Loaded" in VERBS (utils/turns.ts:194), so every skill call becomes a row like any Read or Edit.
  • The counter (✦ 2 skills) is a separate toggle that opens a "chapters" list: which skill was in charge, when it started, how long it ran. countsPhrase leaves skills out of the header sentence on purpose ("each has its own control"), and that control went into the log footer (TurnActivity.svelte:641).
  • Why it looks like a step: the footer sits directly under the last row with no rule or gap. It starts at the same left edge, leads with the same sparkles icon the skill row uses, and has the same muted ghost-button look. Opening it adds a second list of skill rows under the first. So one fact gets shown three times, in three styles that all look alike.

B, skill chapters. It fixes the cause, not the look: one concept (a skill governed these steps) gets one rendering, in the place you're already reading. The "Loaded" verb, the counter, and the chapters list all go away. Turns without skills only change by gaining the ruled totals line.
