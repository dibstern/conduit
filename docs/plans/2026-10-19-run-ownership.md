# Provider run ownership

Each committed `send_turn` reserves a fresh conduit run id in its durable payload and a `provider_runs` row. A run has `id`, `session_id`, `status`, `requested_at`, `started_at`, and `completed_at`. Status is pending, running, completed, error, interrupted, or joined. `turns.run_id` records acceptance, separately from provider message parents and input ids. Runtime and stored event envelopes carry optional `runId`; projectors read this field, so it is persisted metadata with a consumer.

The outbox transaction reserves the run before execution. Claude carries that reservation through runner input and replay. Its `command_lifecycle.started` frame emits `run.started` with the accepted input id and reserved run id. If a root run is still active, the input joins it and its unused reservation becomes joined. After a terminal result, the next started frame uses its own reservation. A delayed OpenCode echo of an already-ended send retains its exact reserved or accepted run and inherits that run's recorded terminal state and time, without reopening it. Queueing and sending never join a turn. All translated root output uses the resolved run; terminal output retains that run even while later input waits. Delayed output with a known message or tool owner retains that original run; output whose owner cannot be resolved stays unplaced. OpenCode uses the matching user-message echo as its input acceptance acknowledgement, retains message-to-run ownership for subsequent output, and treats session idle/error as the root terminal boundary. `emitsMessageParentIds` continues to link assistant messages to inputs. An external OpenCode input has no local outbox commit; its live native user echo is explicit acceptance and allocates a conduit run there. A reserved local id with no matching command, a REST snapshot, or an unplaceable signal cannot create an observed run.

External native OpenCode echoes reuse their exact recorded acceptance on reconnect. A newly observed external input joins the sole running run or starts a fresh conduit run at acceptance; its native message id identifies that acceptance without creating a local `messages.input_id`. Only live SSE user echoes establish this ownership, never historical backfill.

`run.started` activates the resolved run and associates the accepted input's turn. A continuation carries an explicit user-message reference to the cut-off turn; it never selects an input by age. Only a terminal event stamped with that run closes its accepted turns. Starting another input or reply, an unowned busy/idle signal, and provider message ids cannot close them. Duplicate terminal events do not close a run again. Known-run usage or model corrections may still update accounting without moving its terminal boundary. The shell completion identity also comes from accepted run membership. Unowned terminal events and stale owned events cannot advance shell completion or settle children. Usage corrections attach only to the explicitly named input or reply owner; completion still closes every run member. Historical REST snapshots retain their historical display projection without deciding live run completion. Inherited fork terminal facts preserve historical attention only; they cannot change runtime completion identity, status, child sessions, or live turn state. Existing legacy attention remains durable baseline data when no run ownership can be reconstructed.

An owned error or interruption before intake may close the exact pending input named by `userMessageId`, while leaving `turns.run_id` and `started_at` null. This records failed delivery without inventing acceptance or an answered-input identity. No successful terminal can use this exception. Claude cleanup takes this owner from the current input's unstarted waiter; Stop waits on the existing query setup lock when the context is still being prepared. This prevents an unowned cleanup end followed by a second command end, preserves queue pause, and lets a steered slash command interrupt once.

Inbox busy is a single read of the session's outstanding run status, pending or running. Approval and usage-limit facts remain available for their own routing decisions but do not contribute to busy. Outbox failure, cancellation, runner loss, and daemon-kill recovery must settle the reserved/active run explicitly, preserving the existing command drain and recovery contracts.

Command completion and provider intake are separate facts. An OpenCode session-wide idle notification cannot complete a particular pending command or its unaccepted reservation. A single pure waiter snapshot captures command, reservation, exact user input, and Deferred identity. Owned terminal ingestion commits first, then resolves only the command waiters whose input and reservation both match that run's recorded acceptance cohort. Completion still runs if an observer fails after commit; a failed or rejected transaction resolves nothing. Session-wide success broadcasts and synthetic success for unaccepted reservations are removed. Confirmed instance stop can still fail the exact captured command attempts, including sends awaiting intake, through the same ingestion and completion path.

A surviving pre-upgrade runner cannot stamp a new run id. Its successful replay therefore closes only the exact migration-authored reservation carried by that command, atomically with settling the current outbox attempt. This compatibility completion does not emit acceptance or associate the historical turn with a run. Ordinary unowned modern output never acquires this authority.

Failure settlement retains both run and input identity. Processing timeouts capture the command input (the cut-off user message for continuation) when armed. Runner exit carries the failed command cohort's exact inputs into the existing session-run settlement path. A synthetic exit end can then close a placed pending input without filling `run_id` or `started_at`, even if it commits before the command-specific failure callback. Later reservations remain outside the exited cohort, and the closed failed turn preserves queue pause.

Failure cleanup may place an unsent user message after its reservation already ended. That creation carries the same explicit run id; a new turn inherits only a matching recorded error/interruption and its original end time, keeping `run_id` and `started_at` null. A successful end cannot supply this initial state, and an existing turn is never overwritten. OpenCode failure placement uses the same reserved native message id as the send and its exact failure owner, so a delayed echo updates that turn rather than creating another input row.

Foreground commands keep the existing direct outbox claim and may reach an active provider run, including several steers before any intake acknowledgement. Delivery does not join them to the run; each input still waits for its own provider intake event. There is no foreground session fence or intake-dependent steering exception. The v6co.3 background drain retains its original per-session ordering and live-command exclusion. Upgrade keeps a legacy executing command busy by giving its reservation running status, and the existing runner recovery settles that exact reservation with owned events.

Conduit failures require an explicit run or input owner. Delayed processing, continuation, and prompt-response callbacks capture their reservation or the exact asked event's run before arming; acceptance resolves a reservation through `run.started.requestedRunId`. They never look up a reused turn's current run when firing. A terminal owner's late response or acknowledgement cannot replace the newer run's processing timer. Immediate failures before a reservation exists retain their exact input id.

`settleSessionRuns` is the explicit session-wide end path. A fresh provider idle/stopped status, a confirmed process exit, or a provider session-scoped failure authorizes it to enumerate outstanding provider-owned run ids and write an owned interruption/error for each, with a reason. Known native successful ends are retained; unresolved outcomes become interruptions, never invented successes. A local reservation still awaiting intake remains owned by its outbox command, even if delivery has returned: an earlier run's idle/error cannot consume that future input. Exact command failure/recovery settles such a reservation. A confirmed runner exit supplies the failed process's exact command-attempt and accepted-run cohort, checked under the admission lock before releasing a replacement; later reservations survive. Interruption reasons are event data, rather than unused event metadata. Ordinary unowned per-run terminals still cannot close a turn. Duplicate confirmation cannot close an already-ended run again. Queued inputs retain the existing pause after interruption/error and can be resumed explicitly.

Runner exit settlement first acquires the same output queue used by native events and scoped runner failures. A native terminal already being committed wins before synthetic exit settlement checks the run state, preventing both a false failure and duplicate owned failure events. An idle runner's rejected, unaccepted send retains its reservation for retry on the replacement runner.

Startup enumerates outstanding accepted OpenCode runs independently of command status, including native inputs with no outbox row and local inputs whose command completed just before its owned idle committed. It probes the bound provider without starting one, checks session binding, event-store sequence, live-ingress revision, and reconnect generation, then uses the session-wide end path when the provider confirms idle/stopped. The current-input guard accepts any member of the same run. Busy or unavailable responses preserve the run and retry against the frozen startup candidates. Native input acceptance invalidates reconciled idle proofs immediately, before persistence, so a sampled idle cannot end newly accepted work. Recovery and the outbox drain run before inbox startup.

First native sighting persists its directory in `session.created` metadata. `SessionWorkspace.get` reads that fact for startup probes and subsequent sends until an explicit workspace move or reset overrides it. An omitted status alone is not idle confirmation: startup validates that the native session still exists with the same id in the probed directory before normalizing omission to idle. After an explicit persisted workspace move or reset, the native detail can retain its creation directory. A non-branch-rename workspace event preserves this authority even when a reset clears the workspace column. That mismatch requires both the stored workspace and native directory to be non-busy, with native identity/directory rechecked after the additional read. A busy/retrying native scope or changed detail preserves the run. A native-only/default directory mismatch remains unconfirmed. All reads share the existing event/revision/generation commit guards. No extra migration is needed for these safeguards; migration 0069 remains the new ownership migration and shipped migrations remain immutable.

A confirmed OpenCode instance stop snapshots the existing send Deferreds without removing them. After the guarded owned interruption commits, that snapshot resolves those exact waiters with an interrupted result, allowing their outbox claims to settle failed. Each send owns a separate Deferred, so an old confirmation cannot resolve a later send. A rejected guard or failed transaction leaves the waiters available for a later confirmation.

Cursor is also an active local runner. Its initial acceptance is the SDK's `RUNNING` stream frame matching the returned native run id and agent id; SDK 1.0.37 emits this after `markRunStarting`, separately from returning a send handle. A delivered steer acknowledgement (`complete_delivered`) or its uniquely matching appended-user delta accepts that input into the same conduit run; repeated prompt text waits for its exact acknowledgement. Each foreground translator retains that conduit owner through its terminal event, while native run references remain separate. The adapter must reject foreign run frames, avoid accepting an input at send time, preserve separate ownership after a terminal, settle pre-acceptance failures without claiming intake, and leave child output outside the foreground run. A pre-intake failure ends the reserved run and its command, releases inbox busy, and closes its explicitly named pending input without run ownership or answered-input completion identity. Its daemon tests observe that exact failure and a successful subsequent input. Recorded-event tests exercise these boundaries through the session runner.

Append migration 0069 after main's shipped 0068_input_drafts migration. It adds the run table and turn ownership column without changing shipped migrations. Historical completed turns retain null run ownership; no owner is invented from recency. The daemon store importer copies the run table and remaps its references together with session and turn ids. A session-deletion trigger removes its reservations. Existing pending and retryable outbox sends receive stable pending reservations during migration. A legacy running send receives a running reservation with its carried run id and start time, so inbox busy remains true until existing runner recovery writes its owned terminal event. Upgrade does not synthesize a terminal for that executing reservation. Existing unowned open turns are interrupted at upgrade rather than guessed into a new run. Surviving legacy runner output without a carried run id remains unplaced. Pending reservations resume with the carried id. Repeated migration-ledger repair skips upgrade settlement once the ownership column already exists.

Normal startup recovery preserves materialized legacy turn outcomes. A replay into empty read-model tables cannot recover those outcomes from old unowned terminal events: it leaves those turns unowned and pending. The upgrade's legacy interruption is also materialized state, so exact parity for a future destructive rebuild requires a separate durable legacy baseline rather than guessed run ownership.

Tests use the recorded Claude fold and missed-boundary traces through the isolated daemon harness, plus Claude and OpenCode back-to-back sends. Assertions inspect accepted ownership, terminal counts, persisted turn state, and inbox delivery. A normalized JSON artifact records repeatable case outcomes. Existing restart, outbox drain, unanswered-turn, crash, and jyr9 replay tests remain regression gates.
