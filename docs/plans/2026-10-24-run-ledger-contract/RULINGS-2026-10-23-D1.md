# Run Ledger ruling D1: a failed kill never quarantines (82tn.32.2, 2026-10-23)

Supplements AMENDMENT-2026-10-23.md and RULINGS-2026-10-23.md. Where this file
and those (or CONTRACT.md, spec-82tn32.md) disagree, this file wins. The user
approved this design on 2026-10-23 (answers 2A, 3A, 4A with notice option 5A,
5A, 6A in the D1 brainstorm).

## Ruling (Run Ledger, pure decider)

D1-1. The `quarantine` Run Effect is removed from the model. No decision ever
emits it.

D1-2. `kill_and_respawn` has one meaning to the ledger: "the runner is
released". Any outcome the interpreter reports for it (succeeded, retryable,
permanent or delivery unknown) is treated as released. The ledger never learns
whether the old process actually exited; nothing it decides depends on that.

D1-3. On release, the Run that forced the kill stays (or becomes) Ended with
outcome Interrupted, forced. Its Tombstone is unchanged if it already exists.
The native-session fence held for that Run's query is released at the same
moment; no native-session probe is issued for it. The next queued start
proceeds normally.

D1-4. A replacement runner that cannot start is not a ledger concern at kill
time. It surfaces as the ordinary start refusal of the next start.

D1-5. Withdrawn: spec-82tn32.md "A kill that fails quarantines the runner
without taking the project offline" and "A quarantined but live runner keeps
its runs owned". The process watcher still converts runner exit and failed
liveness checks into settle(process lost); it no longer reports quarantine.

OpenCode is unaffected: it has no runner; its Stop path (cancel, native abort,
fence held until a probe confirms idle) stands.

## Runner manager (outside the decider; separate ticket)

- Kill sequence unchanged: SIGTERM, SIGKILL at 3s, short exit deadline; a
  process whose identity (pid plus start time) cannot be verified is never
  signalled.
- Exit confirmed: normal path. Still alive: detach it (close its socket, drop
  its sinks, retire its runner ID so late events are dropped and logged), mark
  its on-disk registration retired, and resolve the replace as released. The
  next message spawns a fresh runner resuming the same native conversation,
  silently.
- Survivor set: identity-verified kill retries at 10s, 30s and 60s, logged. A
  pid that is gone, reused (identity mismatch) or a zombie counts as exited:
  retries stop, no notice. Each survivor has its own schedule and at most one
  notice.
- After the third failed retry, one session-scoped transcript notice (the
  existing `turn.notice` info banner, extended to carry no Run). Wording:
  - signalled but not exited: "The previous run (pid P) was told to stop but
    hasn't exited yet. It can't make further changes and will exit when the
    system releases it."
  - never signalled: "Conduit couldn't confirm pid P is the previous run, so
    it didn't stop it. It may still be running. Stop it manually if it is."
  Skipped if the session was deleted or archived; retries still run. The
  banner stays if the survivor exits later.
- Restart: retired registrations are never re-adopted; they re-enter the
  retry schedule. If two live registrations claim one session, the newer wins
  and the older joins the survivor set.
- The `runner_quarantined` failure code and its non-retryable send path are
  removed.

## Testing

- Oracle: the naive reference is updated to this ruling by an author who reads
  only the contract docs (this file included) and the public model. Property
  traces: a failed kill still ends the Run Interrupted, forced; no quarantine
  effect; the next start proceeds. Quarantine cases are deleted, not adapted.
- Runner manager E2E with real processes: a SIGTERM-ignoring runner is
  SIGKILLed, the normal path runs, a follow-up message resumes the same
  conversation; JSON artifact of pids, signals, timings, resumed native id.
- Survivor schedule through the runner manager's interface with an injected
  clock and process table: 10/30/60s, mismatch and zombie stop without notice,
  one notice with the right wording, retired registration never re-adopted,
  newer registration wins.
- Projector: a session-scoped `turn.notice` persists and replays as the info
  banner.
