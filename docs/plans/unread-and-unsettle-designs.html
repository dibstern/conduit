conduit · Mark unread and Un-settle,
placed in the system

Two verbs the server already has and the UI only half shows. Mark unread has no control anywhere. Un-settle works from the list, but once a session is open it has only a banner that was designed and never built, and auto-settle is about to make that moment common. This page draws four ways to place both verbs, on the phone and the desktop, in the list and inside a session, and ends with one recommendation.

0What every direction shares

The four directions differ only where there is a real choice. Everything below holds in all of them, so the comparison at the end is about placement, not about semantics.

How read works today

  • One timestamp, read_at. Switching to a session writes it. session.unread sets it to null. Any message newer than it makes the row unread again.
  • So opening marks read, not viewing: the write happens on arrival. Stay in a session you just marked unread and it stays unread, unless the client re-opens it on a reconnect or reload.
  • There is no Mark read RPC. Undo, and Mark read by hand, both need one.
  • A hand-marked row and a never-opened row are the same row to the server. Telling them apart needs one column.

Rules every direction keeps

  • Paired verbs flip in place. Menus, sheets and keys show whichever half applies: Mark unread or Mark read, Settle or Un-settle.
  • Neither shelf shows read state, so settled and snoozed rows do not offer Mark unread, the same way Snooze disappears on a settled row.
  • The Unread chip counts live rows only. Settled and snoozed never count, as in §2 of the main doc.
  • Sending a message means "I'm back". It un-settles, it wakes, and it ends a hand-set unread.

Where this meets auto-settle

  • An unread session never auto-settles, so Mark unread also means "keep this in front of me". The auto-settle setting should say so in one line: Sessions you haven't read never auto-settle.
  • Un-settling pauses auto-settle until there is new activity.
  • Auto-settle when idle is a per-session checkbox, on by default. It keeps that label, and that polarity, on every surface.
  • Auto-settled rows read Auto · 1d on the shelf.

Copy

  • Verbs as the menu has them: Mark unread, Mark read, Settle, Un-settle, Auto-settle when idle.
  • Banners and toasts are short sentences, one idea each. No em dashes, no "successfully", no exclamation marks.
  • The icons stay as they are: ● unread, ✓ settle, ↶ un-settle, ☾ snooze, ⚑ pin.

AMenus and keys: marking unread takes you back to the list

The smallest change. No new gesture, no new hover icon, no new state to draw. Mark unread goes into the sheet, the menus and the keys that already exist. Inside a session it does what Gmail does: it marks the session and takes you back to the list, so the rule that opening marks read never has to bend.

Desktop behaves like the phone: the pane returns to its empty state and the focus ring sits on the row you left. The list was already on screen, so this is a surprise if you meant to keep reading.

Keys

  • List focused: u marks unread or read, s settles or un-settles.
  • In a session: ⌘⇧U marks unread and closes, Gmail's ⇧U then back. ⌘⇧S settles or un-settles and stays.
  • ⌘Z undoes either for five seconds.

Good

  • Nothing new to learn, draw or test beyond two menu items.
  • No hold rule: you never look at a session you just marked unread.
  • The row shows exactly what the server stores. No new column.

Risky

  • A two-day-old session reappears with a Done pill, as if it had just finished. That misreports what happened.
  • Closing the pane on desktop, where the list is already visible, punishes the person who wanted to keep reading.
  • Mark unread stays item seven of a menu, so its second job, keeping a session from auto-settling, is invisible.

Cost

  • Two menu items, one sheet item, u and ⌘⇧U.
  • A Mark read RPC for Undo.
  • The banner's second row.

★Recommendation: B's tray, A's banner, and one rule for leaving

A hybrid, because each direction is right about one thing. B is right that the held stage of swipe right is wasted and that a hand-marked row should not pretend it just finished. A is right that the banner is the place to un-settle and that the setting belongs there too. Neither C's chip nor D's dot earns its cost on a phone.

What we build

  • Unread is a flag, not a tier. A hand-marked row keeps its place and its time, lifts to full ink, and gets the same dot as Done, unread. The tier and the pill already say which kind it is, so no second dot shape. Both count in the Unread chip.
  • Mark unread puts you where the list is. On a phone that means going back to it, with the toast on arrival. On desktop the list is already on screen, so you stay, the open row gets the dot, and the flag holds until you open another session or send a message. One rule; the platforms just start in different places.
  • Short swipe right holds Settle and Unread; full swipe settles, as today. Now both swipes read the same way: a short swipe offers, a full swipe commits.
  • Desktop hover is unchanged. Right-click and u are one step each; a fifth icon would squeeze every title for the least frequent verb.
  • Menus group the paired verbs: Settle, Snooze, Pin, Mark unread, with the checkbox under Settle. Same order in the sheet, right-click, session ⋯ and tray.
  • The banner stays where the main doc put it, above the composer. When the server did the settling, a second row carries Auto-settle when idle, in the menu's own words.
  • Keys: u and s with the list or transcript focused; ⌘⇧U and ⌘⇧S from anywhere, including the composer.

Why not the others, whole

  • A whole: a two-day-old session wearing a fresh Done pill misreports what happened, and closing the desktop pane punishes reading on.
  • B whole: the hover icon is the wrong trade, and the one-time offer after un-settling fires while output streams, when nobody is looking at a banner.
  • C: the right idea for a later "state everywhere" pass, but it spends bar 18's width and moves un-settle away from the composer, where the decision is made.
  • D: a pointer-first idea in a phone-first product. Worth revisiting as a desktop-only accelerator once the flag exists.

What it costs

  • MarkSessionRead RPC, for Undo and Mark read by hand.
  • unread_marked_at: set by session.unread, cleared by session.read, so tier derivation can tell a flag from fresh output.
  • A client-side hold: skip the read write when re-attaching to the session you marked, until you open a different one.
  • A second button in the swipe tray; menu and sheet reorder; the banner's second row; two chords.
About two days, and each piece ships alone.

Open questions for you

  • ⌘⇧U needs checking in Safari, Chrome and Firefox on macOS before we commit to it.
  • Should settling clear unread? This page says no, as Gmail's archive doesn't, so un-settling an unread session brings it back bold. The auto-settle guard makes this rare either way.
  • Should the desktop hold survive a reload? Proposed: in memory only, so a reload counts as opening. Putting it in the URL is possible but leaks into shared links.
  • Mark unread on a row that needs you: allowed here, since it is harmless and means "remind me after I answer". Say if you would rather grey it out, like Settle.
