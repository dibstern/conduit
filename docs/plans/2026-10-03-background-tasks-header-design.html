Data check

Checked against the installed Claude Agent SDK (0.3.280) type definitions and conduit's Claude translator. Task names below are the kind Claude really writes; I sampled them from this session's own background tasks.

Shown in the designWhere the SDK has itConduit today
Task countYes. background_tasks_changed sends the full live list on every change (and again on reconnect).Dropped. Only "any tasks?" survives.
Task nameYes. description on each task, e.g. "Run codex to implement ticket .1". Sentences, so they need truncating.Dropped.
Kind (shell, subagent, workflow)Yes. task_type.Dropped.
Age ("6m")Not directly. The list has no start time. Conduit can note the time it first sees each task. That's accurate, because conduit starts the Claude process and sees every task begin.Not recorded.
Shell commandIndirect. Each task points at the tool call that started it, and that call holds the command.In the transcript, not linked.
Stop one taskYes. stopTask(id).Not wired. Stop interrupts the turn, which kills every task.
One catch with per-task stop. To use it, conduit declares a per-task stop control to the SDK. After that, the composer's main Stop only stops the current turn and leaves background agents running. That's arguably better, but it changes what Stop means, so it's your call. The pull-down below assumes per-task stop is on, plus "Stop all".
